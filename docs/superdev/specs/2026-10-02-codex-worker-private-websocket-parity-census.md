# Codex worker private WebSocket parity — census

**Date:** 2026-10-02
**Scope:** the shared `codex-worker` service's private app-server transport, public attach behavior, and remote agent visibility.

- **MEASURED:** the running managed service owns public `ws://127.0.0.1:4500` in the Python `codex-worker` process and starts its Codex child with `codex app-server --listen unix:///var/folders/.../scw-501-global/c`; the separately started comparison process runs `codex app-server --listen ws://127.0.0.1:4501`. Evidence command: `ps -ww -p 11784,11831,11836,40889,40890 -o pid=,ppid=,command=`.
- **MEASURED:** the direct 4501 endpoint remains stable with plugins enabled, while the 4500 gateway repeatedly reconnects. A controlled comparison also showed `--disable remote_plugin` does not stop the 4500 loop; `--disable plugins` does. The operator has separately stated that 4501 works and must not be stopped.
- **MEASURED:** the installed and canonical worker transport declare `MAX_FRAME_BYTES = 4 * 1024 * 1024`; the observed `plugin/list` response was 12,045,587 bytes. Evidence command: `rg -n "4194304|4\\s*\\*\\s*1024|max_size|plugin/list" .../codex_worker`; canonical source: `skills/subagent-driven-development/scripts/codex_worker/websocket_transport.py:14-45`.
- **READ:** the shared-service design deliberately places a maintenance-aware public gateway in front of a private Unix-WebSocket Codex child. It requires one-to-one frontend/backend forwarding so external TUI mutations participate in the maintenance drain (`docs/superdev/specs/2026-08-28-codex-worker-shared-app-server-design.md:65-88,92-171`; decision D17 at `docs/superdev/specs/2026-08-28-codex-worker-shared-app-server-decisions.md:366-416`).
- **READ:** `GlobalWorkerService.start()` currently binds the gateway first, constructs `private_endpoint` as `unix://<private socket>`, launches `codex app-server --listen <private_endpoint>`, waits for the private socket, and opens the broker connection (`skills/subagent-driven-development/scripts/codex_worker/service.py:260-286`).
- **READ:** `WebSocketGateway` currently rejects any backend endpoint not beginning with `unix://`; both its backend connector and its public server use the shared 4 MiB maximum (`skills/subagent-driven-development/scripts/codex_worker/websocket_gateway.py:195-220,250-313,440-460`).
- **READ:** the existing fake Codex fixture already supports both `unix://` and `ws://HOST:PORT` listener modes, so private TCP-WebSocket lifecycle tests can reuse the real test seam (`tests/codex-worker/fake_codex.py:353-370`).
- **READ:** current service tests pin a Unix private endpoint, owner-only socket permissions, gateway-first binding, and collision refusal (`tests/codex-worker/test_service.py:383-430`). Those expectations must be deliberately retained, replaced, or regenerated rather than silently weakened.
- **READ:** the original architecture requires the gateway to remain the public bind authority and the maintenance gate to classify and drain mutations. Directly exposing the child on the public endpoint would discard those guarantees (`docs/superdev/specs/2026-08-28-codex-worker-shared-app-server-design.md:98-125,145-164`).
- **FLAGGED:** the native Codex `ws://` listener exposes `/readyz` and `/healthz`; the worker gateway currently exposes WebSocket forwarding only. Whether public health endpoints are required for parity remains undecided.
- **MEASURED:** `codex --remote ws://127.0.0.1:4501 agents` opens the native Agent command center and lists the agents belonging to that app-server service. The operator confirmed that its 12-task inventory is correctly smaller than another service's 22-task inventory; cross-service aggregation is not required. Evidence commands: `codex --remote ws://127.0.0.1:4501 agents --help` and an interactive read-only attach/detach to the command center.
- **READ:** the worker gateway already admits both `thread/list` and `thread/loaded/list`, which are required inventory methods for native remote agent browsing (`skills/subagent-driven-development/scripts/codex_worker/websocket_gateway.py:20-47`).
- **FLAGGED:** an operator-supplied private backend URL needs an ownership rule. A URL may mean “spawn and own a child at this address” or “connect to an externally owned app-server”; those lifecycles cannot safely share implicit stop/restart behavior.
